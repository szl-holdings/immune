## Domain: fail-closed build-info provenance for declared Python sources

## Leaders studied (web-verified 2026-11-22)

1. **SLSA v1.2** (November 2025 spec; OWASP guidance). Build track L1: provenance exists; L2: signed, generated by hosted build service; L3: hardened platform, unforgeable provenance.
2. **in-toto** - cryptographically verifiable attestations linking every step source-to-artifact.
3. **sigstore/cosign** - signing + attestation management; Notary Project (notation) for PKI-anchored OCI artifacts.
4. **SLSA GitHub Generator** - L3 provenance for GitHub Actions builds; **slsa-verifier** for consumer-side verification.

2. (slsa-verifier class) Verify before display: fail closed when provenance is absent, unverifiable, or stale.
3. (in-toto/sigstore) Bind build-info to a step-linked attestation chain compatible with the estate receipt doctrine.
